# AIMaster architecture and release boundary

The installed unit is `skills/aimaster/`: a short SKILL entry, targeted references, built-in read-only guide catalog, Python 3.11+ standard-library runtime, vanilla JS dashboard, and CLI scripts. Persistent workspaces, projects, media, user guides, library, preferences and family receipts live outside it. A Git clone is one install origin; a standalone npx-installed skill folder is another. Public package data excludes private project receipts, credentials and account media.

Creator Studio's `ProjectStore` is the canonical creative state. Authoring, decisions and stage approvals use expected revision and history. The action ledger holds queued/running/terminal jobs; the operator leases one workspace and invokes an explicit Codex or Claude CLI adapter. Dashboard and Telegram/Mini App use the same store and scoped HTTP routes. An inactive controller yields `needs_chat` with an exact copy request; it does not revive a desktop chat. Guided paid actions require a current private route binding to prompt/reference basis and one scoped grant. Automatic mode gets standing authority only after a short approved brief. Unknown external outcomes are reconciled through read-back, not a second POST.

Built-in guide metadata and SHA identify exact kind/modality/task/provider/model/version. User guides use a separate registry and folder. A project records its own exact guide choice or none; the chosen file is revalidated when used. The provider catalog and current exposed tools establish route and model availability. Reference binding is per operation: canonical Studio IDs are distinct from native tags and schema fields, which must be observed and validated. Uploaded assets retain source provenance and identity; library cards cross projects without becoming part of the installed package.

Video/mixed projects choose `materials` or `montage`. Materials approval verifies an immutable selected-assets manifest and does not invent an MP4. Montage uses a selected media handoff, renders a base version, optionally improves it with editable styles/overlays, then exports portable assets/composition/final MP4. AIEditing supplies a relevant format workshop, not a substitute renderer. Versions and their hashes stay available through improvement and relocation.

Family setup treats AIMaster, SYNTX and AIEditing as local components with package/config backups, compatibility gating and possible rollback. Higgsfield, Magnific and fal are hosted endpoints: local connector state can be restored, vendor server versions cannot. `installed`, `configured`, `authenticated` and `available` are separate statuses. Auto-update is opt-in once and runs at an idle new-session boundary. It verifies official provenance and target data readers, and preserves the running package and user data on failure. Old code cannot read all newer metadata; a `compatibility_blocked` rollback is the safe result. Older-compatible workspace snapshots restore to a separate directory.

Verification layers are distinct: unit/CLI/UI tests, synthetic clean-home install, actual host and provider login, paid creation read-back, native OS/browser operation, and published release read-back. A local PASS proves only its tested layer. `skills/aimaster/scripts/check_project.py` runs the bundled Python, static JS, UI, compile and diff gates. Release VERSION, CI, tag and publication are separate owner operations; published evidence is recorded in [RELEASES.md](../RELEASES.md) and GitHub Actions.

Provider acknowledgements, completed GET receipts, locator renewals and computed artifact verification
are separate private evidence. Parent collection has exact provider origins, public-address-pinned TLS,
bounded GET and typed original metadata checks. It uses AssetIndex and the existing authoring transaction,
then appends a reconciliation event; it never dispatches generation. The selected guide SHA remains frozen
for old-result recovery while new generation revalidates the current bundle. See the package's
[recovery contract](../skills/aimaster/references/provider-recovery.md).

Discover provider-agnostic scenario guides before choosing a service. After selecting the exact provider, model family, model and version, match the image or motion guide to that route and the requested task; task values describe the actual genre/action and need not equal a UI stage name. Persist the selected reference and SHA, then resolve and revalidate that exact choice immediately before use. A stale guide is not silently replaced. See `skills/aimaster/studio/guide_catalog.py` and `skills/aimaster/scripts/guide_registry.py`.

Claude authoring is one typed request bound to the active ledger job, project, revision and operator controller. It calls existing authoring APIs; it is not a free shell or a dispatcher loop. The parent validates returned identity, revision, canonical state, history and semantic output IDs before recording success. A host may return a null state hash; the parent computes the canonical digest independently and checks a supplied hash when present. Multiple operations accumulate their output IDs. A claimed ID that was not created, or a missing expected ID, is not a successful result. See `skills/aimaster/studio/job_authoring.py`, `skills/aimaster/studio/operator_adapters.py` and `skills/aimaster/studio/operator.py`.

Provider acknowledgement, completed-creation GET receipt, original collection and canonical attachment are separate phases. The parent validates the immutable receipt and basis, verifies downloaded bytes and media metadata, then registers and attaches through `AssetIndex` and the existing authoring transaction. A crash can reconcile/read back or repeat GET; it must not repeat paid dispatch. See `skills/aimaster/studio/provider_collection.py` and `skills/aimaster/studio/provider_receipts.py`.

Montage overlays use typed, validated operations in the composition canvas coordinate space; arbitrary SVG/HTML/CSS input is not accepted. The portable export copies only referenced local dependencies, rejects external/private absolute paths, hashes the files and verifies the manifest; an existing destination is refused. Dirty detection compares authored inline script bodies against the immutable version snapshot, so Studio-normalized HTML metadata and IDs do not falsely mark a version changed. See `skills/aimaster/studio/montage/overlays.py`, `skills/aimaster/studio/montage/portable.py`, `skills/aimaster/studio/montage/export.py` and `skills/aimaster/studio/montage/version_diff.py`.

Presentation preferences have one canonical workspace store at the owner/CSRF-protected `/api/preferences`, with exact locale/theme/view/rail enums outside creative state. Clients import workspace preferences once at boot and may keep an origin-local first-frame fallback; background creative polls do not apply another client's preference changes. See `skills/aimaster/studio/workspace_preferences.py`, `skills/aimaster/studio/http_app.py` and `skills/aimaster/studio/static/ui/v2/preferences.js`.

These contracts describe implemented code; they do not prove all host/provider routes, authentication, paid outcomes, every native OS, live browser behavior or publication. Verification evidence is layered; public release records and GitHub Actions show only the published checks and outcomes they report.

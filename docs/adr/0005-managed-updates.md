# ADR 0005. Управляемые обновления семейства

## Контекст

Семейство устанавливается без полного исходного дерева. Его локальные компоненты и размещённые сервисы имеют разные способы обновления, а пользовательские рабочие области, инструкции и библиотека должны оставаться вне поставки.

## Решение

Для каждого компонента различать поддержку, установку, настройку, аутентификацию и фактическую доступность. Проверка обновлений выполняется по выбранной владельцем политике при начале новой сессии. Локальную замену проводить через подготовку, проверку, резервную копию, атомарное переключение и повторное чтение результата; общая аренда операции исключает переключение во время активной работы. Откат разрешать лишь после проверки совместимости данных и текущего состояния. Текстовые файлы поставки имеют стабильную форму строк LF; бинарные ресурсы сохраняют бинарный формат.

## Почему

Одинаковый механизм обновления нельзя применять к установкам из разных источников и размещённым сервисам. Откат только исполняемых файлов при несовместимых данных создаёт ложную безопасность, а единый флаг готовности скрывает отсутствие нужной настройки или доступа.

## Последствия

Прерванная загрузка не заменяет рабочий пакет. При несовместимости данные сохраняются, а обновление блокируется с понятным состоянием. Для размещённого маршрута проверяется доступность, но откат его серверной части не обещается. Проверка контрольных сумм поставляемого текста не зависит от настроек checkout; пользовательские файлы вне пакета сохраняют исходные байты.

# ADR 0003. Идентичность элементов библиотеки

## Контекст

Персонажи, товары, места, визуальные стили и связанные голоса используются повторно. Название, файл или внешнее сходство сами по себе не устанавливают идентичность и назначение элемента.

## Решение

Хранить библиотеку отдельно от устанавливаемого пакета. Каждая карточка получает устойчивый идентификатор, подпись, псевдонимы, заметки, метки, ссылки на медиа и историю ревизий. Поиск возвращает кандидатов и основания совпадения; неоднозначные совпадения не выбираются автоматически. При добавлении в проект сохраняются отдельно идентификатор карточки, ссылка проекта и привязка провайдера. Автоматический выбор использует только связи, согласованные с брифом.

## Почему

Сведение карточек по одному имени или контрольной сумме смешивает разные сущности. Копирование заметок в каждый проект создаёт расходящиеся версии, а поиск по всем пользовательским папкам расширяет доступ за пределы задачи.

## Последствия

Удаление карточки библиотеки не удаляет уже сохранённый материал проекта. Визуальный стиль и монтажный профиль остаются разными сущностями. Перенос и повторный импорт должны сохранять идентичность и не раскрывать личные данные библиотеки в поставке.

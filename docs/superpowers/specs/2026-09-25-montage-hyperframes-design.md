# Монтаж на HyperFrames: наглядная сборка ролика

Дата: 2026-09-25. Ветка: `feat/montage-hyperframes`. Решения владельца
получены в диалоге 2026-09-25. Проба осуществимости — HyperFrames 0.8.75 на
macOS, 2026-09-25 (итоги в разделе «Факты пробы»).

## Проблема

Этап «Сборка» сейчас — заглушка. Агент как-то собирает ролик вне навыка и
регистрирует готовый файл (`creator_studio.py assembly set`,
`studio/authoring_qa.py:41-90`). Канон этапа — три строки
(`references/phases/06-assembly.md`). У человека нет ни монтажа, ни версий, ни
способа поправить сборку иначе как словами, ни кнопки «скачать».

## Решения владельца

- Монтаж делаем на HyperFrames (open-source HeyGen, Apache-2.0, npm
  `hyperframes`). Вариант 1: монтажный стол — HyperFrames Studio в соседней
  вкладке. Архитектура такая, чтобы потом безболезненно попробовать вариант 2 —
  свой стол внутри дашборда.
- В первой версии обязательно: таймлайн и клипы; нарезка любого элемента
  (брать только нужные куски); звук слоями с громкостью; текст и титры;
  переходы; сборка MP4.
- Автопилот: весь монтаж делает агент сам, без вопросов. Режим с уточнениями:
  агент собирает черновик и MP4, человек дорабатывает наглядно, агент
  пересобирает по его правкам с точностью до кадра.
- Версии не стираются; можно бесконечно ходить назад и вперёд.
- После сборки — «Скачать» и «Показать в папке» с путём к файлу.
- Телефон: Mini App показывает сборку; монтажный стол на телефоне пробуем
  через туннель, но только за нашей проверкой входа.
- Скиллы HyperFrames для агента ставятся вместе с навыком.
- Работа в ветке; владелец тестирует; потом слияние и выпуск.

## Факты пробы (HyperFrames 0.8.75, macOS)

- Studio: `hyperframes preview --foreground --json --no-open --port N`, слушает
  только 127.0.0.1, готова за ~1 с. Видны все дорожки. Сдвиг, обрезка краёв
  (с верным `data-media-start`), бритва, undo/redo работают мышью и
  **пишутся в `index.html` на диске**. Правку из CLI открытая Studio
  подхватывает меньше чем за секунду.
- Studio при открытии переписывает `index.html` (проставляет `data-hf-id`,
  нормализует разметку) — текстовый diff шумный.
- Медиа — только внутри папки композиции: `../`, абсолютные пути и `file://`
  lint отклоняет. Симлинк работает, но на Windows требует прав.
- CLI для агента: `timeline --json` (дорожки и клипы), `move`, `trim`, `split`,
  `set` (volume, rate, track), `timeline undo <квитанция>`. Отличия от Studio:
  `trim` начала не сдвигает `data-media-start`; CLI не удлиняет композицию сам.
- Рендер: headless Chrome + FFmpeg, MP4 1080×1920 30 fps со звуком за ~15 с
  на 15-секундный ролик. Первый рендер молча скачивает `chrome-headless-shell`
  (~100 МБ). При рендере подгружаются GSAP (jsDelivr) и шрифт Inter (Google
  Fonts). Пути с кириллицей и пробелами работают.
- `init` по умолчанию ставит скиллы глобально (`HYPERFRAMES_SKIP_SKILLS=1`
  отключает) и кладёт в папку `CLAUDE.md` и `AGENTS.md`.
- Телеметрия: CLI — выключается переменной; интерфейс Studio шлёт события в
  PostHog независимо от переменных, отключается только ключом localStorage
  `hyperframes-studio:telemetryDisabled=1` на origin Studio.
- Нужны Node ≥ 22 и FFmpeg. Интерфейс Studio только на английском.

## Как это выглядит для человека

**Режим с уточнениями.**

1. Все видео по сценам одобрены → агент делает черновой монтаж: клипы по
   порядку сценария, голос/музыка/шумы/атмосфера на своих дорожках, субтитры
   из текста сцен, мягкие переходы между сценами. Сразу собирает MP4 —
   версия v1.
2. Экран «Сборка»: плеер текущей версии; под ним «Скачать», «Показать в папке»
   и путь к файлу; листалка версий; схема слоёв; две главные кнопки —
   «Открыть монтажный стол» и «Собрать ролик → чат».
3. «Открыть монтажный стол» — Studio в новой вкладке на рабочем монтаже.
   Правки сохраняются сами.
4. «Собрать ролик → чат» — агент читает изменения, пересказывает их по-человечески,
   проверяет монтаж, собирает MP4 новой версией.
5. Правки словами в чате агент вносит в тот же монтаж.
6. Любую версию можно «Сделать текущей» — монтаж возвращается к ней; версии не
   удаляются.
7. «Принять» — как сейчас.

**Автопилот:** черновик → проверка → сборка → проверка кадров и звука →
принятие, без вопросов. Стол потом можно открыть и доработать.

**Телефон (Mini App):** плеер, версии, схема слоёв, «Прислать в Telegram».
Монтажный стол — отдельным этапом (см. «Телефон»).

Фото-проекты монтажом не затрагиваются: их сборка — принятая картинка, как
сейчас. Монтаж — для проектов `video` и `mixed`, в обоих `gen_mode`.

## Раскладка файлов

Внутри папки проекта (`<workspace>/projects/<id>/`, или корня проекта при
старой раскладке — `studio/workspace.py:57-94`):

```
montage/
├── current/                 рабочий монтаж — его правят Studio и агент
│   ├── index.html           композиция HyperFrames (источник правды о монтаже)
│   ├── hyperframes.json     конфиг проекта HyperFrames
│   ├── assets/              клипы, звук, картинки, gsap.min.js
│   └── (служебное HyperFrames: .hyperframes/, .waveform-cache/, renders/)
└── versions/
    ├── v001/index.html      снимок композиции этой версии
    ├── v001/meta.json       {version, created_at, by: agent|owner|autopilot,
    │                         based_on, summary, changes[], asset_id, model_hash}
    └── v002/…
```

- `assets/` заполняется жёсткими ссылками на файлы из `<workspace>/media/`;
  если жёсткая ссылка невозможна (другой диск, ФС без ссылок) — копией.
  Симлинки не используются (Windows).
- MP4 каждой версии кладётся в `<workspace>/media/<project-id>/montage/v003.mp4`
  и регистрируется в `AssetIndex` с ролью `result` — иначе `assembly set` его
  не примет (`studio/assets.py:973-1036`, `authoring_qa.py:82`).
- В `state.json` — компактный раздел `montage`: `{current_version, versions:
  [{id, asset_id, created_at, by, based_on, summary}], canvas: {width,
  height}}`. Меняется через обычную транзакцию с `expected_revision` и пишет
  записи в историю проекта. Схема монтажа живёт только в `index.html`.
- «Сделать текущей» копирует `versions/vNNN/index.html` в `current/`, пишет
  запись в историю и `current_version`; сами версии неизменяемы.
- Старые проекты без `montage/` работают как раньше; раздел появляется с первым
  `montage draft`.

## Компоненты

Новый пакет `skills/aimaster/studio/montage/`, по файлу на ответственность:

| Модуль | Что делает |
|---|---|
| `engine.py` | Находит установленный HyperFrames закреплённой версии, запускает его CLI без shell, по полному пути (Windows: `node.exe` + скрипт пакета, не `npx.cmd`), с таймаутами и переменными `HYPERFRAMES_NO_UPDATE_CHECK=1`, `HYPERFRAMES_NO_AUTO_INSTALL=1`, `HYPERFRAMES_NO_TELEMETRY=1`, `HYPERFRAMES_SKIP_SKILLS=1`; `--frames-cache-dir` в служебную папку. Разбирает JSON-вывод. |
| `engine.json` | Закреплённая версия: пакет, версия движка, ссылка на выпуск скиллов. Меняется только выпуском навыка после CI. |
| `canvas.py` | Размер кадра: по ширине/высоте первого выбранного видеоклипа из `AssetIndex`; если неизвестно — 1080×1920. |
| `draft.py` | Чистая функция «проект → композиция»: клипы по `order` сцен с `start_ms/end_ms`, выбранные результаты (`domain_positions.current_member`), аудиослои `voice/music/fx/atmos` с громкостью по умолчанию, субтитры из активной версии текста сцены, переходы через `data-fade-in/out`. Без GSAP-анимаций в черновике, без внешних URL. |
| `media_sync.py` | Жёсткая ссылка или копия медиа в `current/assets/`; проверка, что все `src` композиции существуют внутри папки. |
| `model.py` | Нейтральная модель монтажа из `timeline --json` (дорожки: видео, титры, голос, музыка, шумы, атмосфера; клипы: id, вид, start, duration, media_start, volume, src → сцена/слой). Хэш модели. Смысловой diff двух моделей → список изменений человеческим языком. |
| `versions.py` | Создать версию, список, сделать текущей, «есть несобранные правки» (хэш модели `current` ≠ хэш текущей версии). |
| `edit.py` | Правки агента поверх CLI HyperFrames с выравниванием под Studio: обрезка начала сдвигает `data-media-start`; сдвиг за конец удлиняет корень; громкость, разрезание, удаление, титр (добавить/изменить текст/время). |
| `render.py` | `lint` → рендер MP4 → проверка ffprobe (длительность, размер, есть звук, если есть аудиослои) → регистрация ассета → версия → `assembly set`. Ошибка на любом шаге — версии нет, понятное сообщение. |
| `desk.py` | Интерфейс «монтажный стол»: `open(project) → url`, `close(project)`, `status(project)`. Реализация `StudioDesk`: процесс `preview` на свободном порту для `current/`, один на проект, остановка при закрытии, простое и выходе сервера. Вариант 2 позже — другая реализация того же интерфейса. |

CLI навыка (`scripts/creator_studio.py montage …`), все с `--json`:
`draft`, `status`, `diff`, `edit <op>`, `render`, `restore <version>`,
`open`, `close`. Меняющие команды принимают `--expected-revision`.

Сборка локальная и бесплатная: `render` не требует разрешения на трату
(`assemble` и так вне `GRANT_REQUIRED_ACTIONS`, `studio/ledger.py:75`).

## Дашборд: экран «Сборка»

Сверху вниз:

1. Плеер текущей версии (как сейчас — `renderPreview`), длительность.
2. «Скачать» — `GET /assets/<id>?download=1` с `Content-Disposition:
   attachment; filename*=UTF-8''<проект>-v003.mp4`. «Показать в папке» —
   `POST /api/projects/<id>/montage/reveal` (Origin + CSRF, как
   `_authorize_write`, `http_app.py:242-250`): Finder (`open -R`), Проводник
   (`explorer /select,`), Linux — `xdg-open` на папку. Путь к файлу виден
   текстом и копируется.
3. Листалка версий v1…vN: кто собрал, когда, строка «что изменилось»;
   «Сделать текущей» — прямое действие дашборда (`POST
   /api/projects/<id>/montage/restore`, Origin + CSRF): локально, бесплатно,
   обратимо; «Принять» — существующее решение `stage approve`.
4. Схема слоёв (только просмотр): дорожки «Видео», «Титры», «Голос», «Музыка»,
   «Шумы», «Атмосфера», цветные блоки по времени; нажатие — что за клип и
   какой кусок исходника. Плашка «Есть несобранные правки», если монтаж
   менялся после последней сборки.
5. Главные кнопки: «Открыть монтажный стол» (`POST
   /api/projects/<id>/montage/desk`, ответ — URL; открывается в новой вкладке)
   и «Собрать ролик → чат».

Снапшот проекта получает раздел `montage`: версии, текущая, схема слоёв из
`model.py`, флаг несобранных правок, состояние стола и движка
(`installed|missing`). Нет движка — «Монтажный стол не установлен» и
«Установить → чат»; остальной экран работает.

Studio открывается через нашу страницу-переходник на origin Studio, которая
ставит `hyperframes-studio:telemetryDisabled=1` и перенаправляет в Studio. Если
Studio не отдаёт такую страницу — отключение не делаем и честно пишем об этом в
README.

## Установка

`scripts/install.py --install-deps` дополнительно:

1. **Node ≥ 22**: winget `OpenJS.NodeJS.LTS`, brew `node`, Linux — менеджер
   пакетов, если там ≥ 22, иначе понятная инструкция в `next_steps`. Node из
   «только для тестов» становится обязательной зависимостью монтажа.
2. **HyperFrames закреплённой версии** — `npm install --prefix
   <user_data_dir>/tools/hyperframes hyperframes@<версия>`, не глобально, без
   автообновления.
3. **Браузер для рендера** — предзагрузка `chrome-headless-shell` сразу, с
   сообщением «Качаю компонент для сборки видео (~100 МБ)».
4. **Скиллы HyperFrames** — из выпуска той же версии, подключаются в
   `~/.claude/skills/` и `~/.agents/skills/` так же, как наш навык, с пометкой
   «поставлено aimaster». Существующая чужая папка с тем же именем не
   перезаписывается — статус `conflict` в JSON.
5. `--update` обновляет движок и его скиллы до версии из `engine.json`.
6. В JSON-отчёт — раздел `montage`: `node`, `hyperframes`, `browser`,
   `skills` со статусами `installed|found|missing|failed|timeout|conflict`.

Движок без сети: GSAP кладётся в `assets/` композиции локально; черновик не
ссылается на внешние шрифты. Рендер без сети — проверяемое требование; если
HyperFrames всё равно ходит в сеть, это фиксируется как известное ограничение
с описанием.

- Новый `references/montage.md`: команды, правила черновика, как пересказывать

- `references/autopilot.md` — шаг `assembly` через `montage`.
- Промпт «Собрать ролик → чат» (`screen-prompts.js::assembleFinal`)

## Телефон

1. Mini App показывает плеер, версии, схему слоёв (тот же снапшот через
   `MiniAppGateway`, `studio/mini_app.py:134-163`).
2. «Прислать в Telegram» — бот отправляет MP4 владельцу. В боте добавляется
   отправка видео/документа (сейчас есть только `send_message`,
   `creator_studio_bot.py:234-248`). Вызов идёт через эндпоинт, доступный
   только из Mini App-шлюза (он знает владельца).
3. Монтажный стол на телефоне — отдельная проба на реальном телефоне
   владельца. Studio использует абсолютные пути `/api/projects/...`, которые
   совпадают с нашими, поэтому через наш хост её не пробросить: нужен отдельный
   хост туннеля и перед Studio — наш прокси с проверкой входа (сессия после
   проверки `initData`). Без проверки входа Studio наружу не выставляется
   никогда. Если пальцем неудобно — на телефоне остаются просмотр и правки
   словами, это аргумент за вариант 2.
4. «Показать в папке» через Mini App не доступно (только локальный дашборд).

## Ошибки

- Нет Node/HyperFrames/браузера — `montage` статус `missing`, экран и агент
  предлагают установку; черновик и рендер не запускаются, ничего не ломается.
- `lint` с ошибками — версии нет, агент называет ошибку и место.
- Рендер упал или ffprobe не сошёлся — версии нет, MP4 не регистрируется,
  текущая версия не меняется.
- Studio не стартовала за таймаут — понятное сообщение, процесс убит.
- Одновременная правка: Studio и агент пишут один файл; агент перед правкой
  читает модель заново, CLI HyperFrames отдаёт квитанцию для отката.
- Проект изменился (новое видео сцены) после черновика — `montage status`
  показывает, какие клипы устарели; `draft --refresh` заменяет только их.

## Проверка

- Юнит-тесты: `draft` (эталонная композиция из фикстуры проекта), `model` и
  `diff`, `versions`, `media_sync` (жёсткая ссылка/копия), `edit` (обрезка
  начала сдвигает исходник), `engine` (подмена процессов, Windows-ветка),
  установщик (подмена winget/brew/npm), эндпоинты (reveal, desk, download,
  Origin/CSRF), модели экрана (`node --test`).
- CI на ubuntu/macos/windows: установка движка закреплённой версии и
  браузера, черновик из тестовых клипов, `lint`, рендер 3-секундного ролика,
  ffprobe; проверка, что композиция не ссылается на внешние URL; на Linux —
  рендер без сети.
- Сквозная проверка оркестратором на копии проекта владельца: черновик → стол
  → правка мышью → diff → сборка → версии → откат → скачать → показать в
  папке, ширины 1400 и 390 px.
- Критики: кода — установщик, эндпоинты, прокси Studio; логики — канон.
- Владелец: тестовый дашборд из ветки на отдельном порту — сначала копия
  проекта, потом настоящий; затем телефон.

## Этапы

1. Движок и установка (+ CI).
2. Монтаж для агента: пакет `montage`, CLI, канон.
3. Экран «Сборка» — первая проверка владельца.
4. Телефон: Mini App, «Прислать в Telegram», проба Studio через туннель —
   вторая проверка владельца.
5. Слияние и выпуск с разделами «что изменилось / проверено / не проверено».

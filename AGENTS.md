# aimaster — публичный пакет

## Назначение

Переносимый навык и локальная AI Мастерская. README.md — вход для пользователя;
INSTALL_WITH_AGENT.md — установка силами его агента. Навык и runtime лежат в
skills/aimaster/. Реальные проекты и личная база знаний хранятся вне репозитория.

## Границы поставки

Публикуются только публичный навык, документация и правила этой поставки.
Не добавлять личные профили, исходные рабочие проекты, credentials, .env,
медиа пользователя, SQLite, служебные журналы или историю приватного проекта.
Не устанавливать навык владельцу и не менять глобальные каталоги без его команды.
Нельзя обещать универсальное обнаружение во всех агентах.
Поддерживаются macOS, Linux и Windows (нативно, без WSL); runtime требует
Python 3.11+ и только стандартную библиотеку. Каждая правка проходит CI на
трёх ОС (.github/workflows/ci.yml): модульные тесты, тесты интерфейса и смоук
чистой машины scripts/smoke_clean_machine.py. Установка — scripts/install.py.
Обещать в документации можно только то, что покрыто CI или проверено вживую.

## Проверки и статус

Детерминированная проверка: `python3 skills/aimaster/scripts/check_project.py`;
семейные швы: `python3 skills/aimaster/scripts/check_family_e2e.py`;
стили: `python3 skills/aimaster/scripts/build_studio_styles.py --check`.
Целевые тесты и локальные серверы/браузеры запускаются на временных синтетических
проектах. Реальный renderer проверяется отдельно при наличии движка. Установка
владельцу, вход в аккаунты, изменение доступов, платная генерация и внешняя
отправка требуют соответствующей команды владельца. Local PASS не доказывает
эти действия, native OS/device acceptance, финальный CI или публикацию.

## Разработка

Условия использования — LICENSE; его копия в skills/aimaster/LICENSE должна
совпадать. Текущая дата выпуска — VERSION и skills/aimaster/VERSION.
Порядок именования и публикации — RELEASES.md. В main не оставлять незавершённый
код между выпусками: пользовательская команда обновляет эту ветку.
Собственные инструкции и материалы держать вне установки. Изменения движка
для третьих лиц требуют разрешения правообладателя; запросы владельца на
разработку этого репозитория выполняются в согласованных им пределах.

Использовать apply_patch для правок. Не менять runtime ради упаковки.
Служебные каталоги с точкой исключены из Git. Проверки и их фактические результаты
фиксировать честно; не запускать установки или внешние генерации из примеров.

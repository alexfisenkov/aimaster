# Установка aimaster силами агента

Этот файл предназначен для агента пользователя. Выполняйте операции только
локально и только в пределах установки навыка. До начала определите целевую
среду: Codex или Claude Code. Если пользователь не назвал её и текущая среда не
даёт однозначного ответа, задайте один уточняющий вопрос; не выбирайте
наугад. Для других агентов используйте только их официальную документацию по
Agent Skills и явный путь к `SKILL.md`.

## Разрешённые границы

Разрешено проверить наличие `git` и `python3`, а при необходимости установить
только Git и Python 3.11+ через официальный пакетный менеджер операционной
системы. При отсутствии необходимого менеджера пакетов подготовьте его
минимальную установку из официального источника в пределах выданных разрешений;
WSL сначала согласуйте как отдельное изменение системы. Сначала проверяйте,
потом устанавливайте только отсутствующее. Не
нужны Node, npm, pip или сторонние Python-пакеты. Не отключайте защиты, не
угадывайте пароль sudo и не печатайте токены, пароли, cookies или `.env`.

Если нужен админский пароль, перезагрузка или интерактивный логин, остановитесь
и попросите пользователя выполнить только этот конкретный шаг. Не обходите
ограничение и не продолжайте с неподтверждённым результатом.

Запрещены покупки, Telegram/MCP-настройка, платные генерации, автоматический
логин AI-клиента, публикация и запуск creative/media jobs. После установки
навыка остановитесь: сообщите проверенные пути и предложите первый запрос.

Во время установки не изменяйте код в `studio/` и `scripts/`. Соблюдайте
[авторские условия](LICENSE): бесплатно использовать пакет для работы и клиентов
можно, но распространять изменённую сборку или выдавать её за свой продукт без
согласия владельца нельзя. Пользовательские проекты, медиа, база, настройки и
свои инструкции должны храниться вне клона. Если установка обнаружила ошибку
проекта, предложите пользователю создать обращение в
https://github.com/alexfisenkov/aimaster/issues. Ничего не публикуйте без его
согласия и не включайте в обращение личные данные, секреты и содержимое проектов.

## Репозиторий и безопасная установка

Используйте точный URL:
`https://github.com/alexfisenkov/aimaster.git`.

1. Выберите постоянный клон `"$HOME/.local/share/aimaster"` или явно
   согласованный с пользователем абсолютный путь. Не клонируйте репозиторий
   внутрь каталога навыка.
2. Если путь уже существует, не клонируйте поверх него. Убедитесь, что это Git-
   репозиторий, прочитайте `origin` и продолжайте только при точном совпадении
   URL; иначе остановитесь и попросите путь.
3. Проверьте наличие `$REPO_DIR/skills/aimaster/SKILL.md`.
4. Для Codex целевой путь — `"$HOME/.agents/skills/aimaster"`; для Claude Code —
   `"$HOME/.claude/skills/aimaster"`. Оба runtime документируют symlink-навыки.
5. Создайте только отсутствующую родительскую папку и symlink именно на
   `$REPO_DIR/skills/aimaster`. Если target уже существует (включая symlink),
   ничего не перезаписывайте: покажите состояние и спросите пользователя.
6. Не используйте `rm -rf`, force-reset, overwrite или ссылку на весь репозиторий.
   При ошибке `git clone` не создавайте symlink в непроверенную чужую папку.

## Безопасное обновление

Обновляйте только чистый клон с точным `origin`. Никогда не применяйте reset,
stash, force или checkout для обхода локальных изменений. Если пользователь
менял инструкции прямо в клоне, остановитесь и объясните, что его файлы не
удалены: личную адаптацию нужно осознанно сохранить вне установки.

```sh
(
set -eu
AIMASTER_REPO_URL='https://github.com/alexfisenkov/aimaster.git'
AIMASTER_REPO_DIR="${HOME}/.local/share/aimaster"
test -d "$AIMASTER_REPO_DIR/.git"
test "$(git -C "$AIMASTER_REPO_DIR" remote get-url origin)" = "$AIMASTER_REPO_URL"
test "$(git -C "$AIMASTER_REPO_DIR" symbolic-ref --short HEAD)" = main
if test -n "$(git -C "$AIMASTER_REPO_DIR" status --porcelain)"; then
  echo "Обновление остановлено: в папке aimaster есть локальные изменения." >&2
  exit 1
fi
git -C "$AIMASTER_REPO_DIR" pull --ff-only
git -C "$AIMASTER_REPO_DIR" fetch --tags
git -C "$AIMASTER_REPO_DIR" describe --tags --exact-match HEAD
)
```

Команда `describe` должна показать точную метку выпуска. Если метки нет,
не объявляйте обновление завершённым: остановитесь и сообщите пользователю
фактический вывод. По правилам публикации ветка `main` содержит только выпуски,
а метка выпуска указывает на тот же commit.

POSIX-проверка версии должна опираться на `sys.version_info`, например:

```sh
python3 -c 'import sys; print(sys.version); raise SystemExit(0 if sys.version_info >= (3,11) else 1)'
```

### macOS

Если Git отсутствует или Python отсутствует/младше3.11 и Homebrew уже доступен,
установите только нужное (`brew install git` или `brew install python`).
Если Homebrew отсутствует, откройте [brew.sh](https://brew.sh/) и
[Installation](https://docs.brew.sh/Installation), получите официальный
installer, прочитайте его и подготовьте установку. Выполните её, если разрешения
среды позволяют; не ограничивайтесь советом пользователю сделать всё самому.
Пароль администратора и системные диалоги оставьте человеку. Не исполняйте
непроверенный `curl | sh`. Примените официальные Next steps для PATH и проверьте
реально выбранный Python. Не удаляйте и не заменяйте системный Python.

### Ubuntu/Debian

Для отсутствующего Git или Python используйте официальный `apt`: при
необходимости `sudo apt update`, затем `sudo apt install git python3` (только
отсутствующие пакеты). После этого проверьте `sys.version_info`. Если Python
младше 3.11, остановитесь: объясните, что нужен официальный upgrade-путь ОС,
и не называйте установку поддерживаемой.

### Windows

Нативный Windows не поддерживается из-за POSIX-зависимостей (включая
`fcntl`). Предложите официальный [WSL install](https://learn.microsoft.com/en-us/windows/wsl/install)
и, если пользователь согласен, команду `wsl --install` в PowerShell с
администраторскими правами. При требуемой перезагрузке остановитесь и ждите
человека. Весь агент, навык, Python и workspace должны находиться внутри WSL;
не обещайте, что Codex Desktop на host автоматически увидит навык в WSL.

## Завершение

После создания ссылки перечитайте путь и убедитесь, что он разрешается в
skills/aimaster этого клона. Можно выполнить безопасный CLI --help, но не
создавать проекты или запускать сервер. Не называйте обнаружение в интерфейсе
агента подтверждённым, пока оно не наблюдалось в новом чате. Сообщите только
нечувствительные сведения: выбранная среда, путь клона, путь навыка и факт проверки
`SKILL.md`. Затем остановитесь и предложите, например:

> Помоги сделать короткий ролик о [идея]. Сначала уточни аудиторию и ограничения.

Для следующего шага направьте пользователя к
`skills/aimaster/references/getting-started.md`. Не создавайте папку проектов,
проекты, медиа, Telegram credentials и provider configuration автоматически.
Если список навыков клиента не обновился, предложите новый чат или перезапуск.

# Explicit controller and Telegram

`python3 <skill>/scripts/creator_studio_operator.py run WS --agent codex|claude` starts one foreground controller for a workspace. `status WS` reports availability and active action; `stop WS` stops only its own lease. Check host CLI/auth availability first. A Codex or Claude CLI process acts on canonical project state; it cannot silently resume an existing desktop chat. If the host is unavailable, actions return `needs_chat` with exact action/project/revision and a copyable prompt. Claude login is a separate host prerequisite, not something the UI can fabricate.

The dashboard exposes local decisions, guide/library views, project questions, and action status. A guided paid button needs the route set by `creator_studio_operator.py route-set WS ID` for the exact prompt and references, plus a matching `spending` confirmation; the click is one-use consent. Do not treat HTTP 202 or queued as creative success. Read the terminal action and canonical result back. Stale revision means refresh and retry a *decision*, not a paid POST. `outcome_unknown` requires provider read-back before reconciliation.

Telegram `creator_studio_telegram.py setup-ui` accepts a token through protected local UI; do not place it in chat/argv/logs. `run --workspace WS [--agent codex|claude]` may start the same controller explicitly. Bot/Mini App select the exact project and write to the same canonical store. Photo/video/voice/audio/document intake retains provenance; voice needs a real transcription service or a text fallback. A file received in Telegram remains pending until the correct project/stage is selected. If Mini App HTTPS/auth fails, use visible text transport and a retry path. Native Windows/Linux Telegram operation remains unverified until tested on those systems.

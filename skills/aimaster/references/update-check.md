# Family update at a new session

On the first aimaster invocation in a new host session, run `python3 <skill>/scripts/family_update.py session-start --session-id HOST_SESSION_ID --json`. Use a stable ID for that session, not a fresh ID per message. The updater only switches packages if the user opted in once (`family_update.py policy --enabled on --json`) and no active job or unresolved outcome blocks it. Do not interrupt a running job. A failed/offline check leaves current creative work available.

The opt-in covers local AIMaster, SYNTX and AIEditing workshop updates. Personal projects, guides, library and created editing styles/skills live outside those packages. Hosted Higgsfield, Magnific and fal endpoints are checked for current availability; their server code has no client pin or rollback. A configured MCP is not necessarily authenticated or available in the current session: verify tools and a free probe after connector changes, and restart the client if the receipt says so.

Use `family_setup.py status --json` for recorded component state. `family_update.py rollback --component aimaster|syntx|aiediting --json` restores a backed-up local package/config only when its compatibility gate accepts existing data. If it reports `compatibility_blocked`, keep current code/data active and, when needed, restore an older compatible workspace snapshot into a separate copy. Never downgrade the live workspace in place. A failed switch may report `recovery_required`; present that status instead of claiming rollback success. Do not use legacy `install.py --update` as this family protocol.

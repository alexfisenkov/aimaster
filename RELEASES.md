# Выпуски AI Мастерской

Все опубликованные выпуски: https://github.com/alexfisenkov/aimaster/releases

## Как называем выпуски

- Первый выпуск за день: `2026.09.20`.
- Следующий за тот же день: `2026.09.20.1`, затем `2026.09.20.2`.
- Суффикс не нужен, если за день опубликован один выпуск.
- Используем дату в часовом поясе владельца проекта. Уже опубликованные
  названия не переносим на другой код и не переиспользуем.

## Что получает пользователь

Каждому выпуску соответствуют отметка в Git, страница выпуска и файлы VERSION
в корне репозитория и внутри навыка. Номер в обоих файлах одинаковый.
Официальные обновления приходят из этого репозитория; новые правила лицензии
нужно читать вместе с новым выпуском.

## Правило для владельца

Ветка main содержит публикуемую версию. Незавершённые изменения готовить
в отдельной ветке, а не предлагать пользователям как готовое обновление.
Перед выпуском обновить оба файла VERSION, сохранить изменения в Git,
создать новую отметку и опубликовать страницу выпуска для этого же коммита.
В описании отдельно указать, что изменилось и что действительно проверено.
Не заявлять успешные проверки, которые не выполнялись.

Минимальный набор проверок перед выпуском:

```bash
python3 -m unittest discover -s skills/aimaster/scripts -p 'test_*.py'
python3 -m compileall -q skills/aimaster
node --experimental-vm-modules --no-warnings skills/aimaster/scripts/check_static_modules.mjs
git diff --check
```

`node --check` для модулей дашборда не годится: файл, начинающийся с `import`,
он молча пропускает даже с синтаксической ошибкой. Поэтому модули
`studio/static` разбираются скриптом `check_static_modules.mjs` как настоящие
ES-модули.

## 2026.09.21.3

- Для `per_scene` добавлен обязательный continuity choice перед каждой сценой после первой: previous accepted video, previous last frame или independent clip.
- При почти неизменной сцене агент рекомендует продолжение через scene-local `video_reference` с `usage=continue`, но сначала проверяет live schema модели.
- Предыдущее видео копируется в отдельный файл с новой ролью, оригинальный result не изменяется; rejected/hidden/retired/stale варианты не используются автоматически.
- В карточке следующей сцены появилась кнопка «Связать с предыдущей сценой» с точным project/scene/result контекстом.
- Выбор continuity теперь хранится в canonical scene state; runner блокирует генерацию каждой `per_scene`-сцены после первой, пока strategy и требуемый frame/video-reference не подтверждены read-back и не связаны с exact accepted result непосредственно предыдущей сцены.
- Тот же continuity guard применяется к payload-only `vary` и `regenerate`, поэтому старый результат не обходит обязательный выбор.
- Provider-native reference tags теперь проходят обязательную машинную проверку перед генерацией: карта содержит provider/route/model/revision/reference_id/asset_id, все inline-теги/mention chips должны точно присутствовать в финальном промпте, а structured inputs — иметь однозначные slots.
- Проверка ловит пропущенные и дублированные теги, оставшиеся canonical-теги, неподтверждённые rich mention chips и совпадения вроде `@img1` внутри `@img10`.
- Любой canonical `@IMG_NN`/`@VID_NN`/`@VOICE_NN`, которого нет в manifest как подтверждённого native token, блокирует запуск даже при пустом manifest.
- Для claimed jobs validator сравнивает manifest с точным frozen context из `claim`, включая полный набор canonical reference/asset IDs и revision; пропущенный текущий референс блокирует запуск.

## 2026.09.21.8

Что изменилось:

- Дашборд снова открывается. С выпуска `2026.09.21.1` в модуле `studio/static/ui/step-plan.js` стояла лишняя запятая в тернарном операторе; браузер прерывал загрузку интерфейса с `SyntaxError: Unexpected token ','`, и после шапки экран оставался пустым при любом непустом проекте. Проверка `node --check` эту ошибку не ловила: файлы, начинающиеся с `import`, она пропускает молча. Добавлен `scripts/check_static_modules.mjs`, который разбирает все модули дашборда как настоящие ES-модули; он включён в порядок выпуска выше.
- Mini App теперь включается при реальном запуске из Telegram. Раньше режим определялся строгим сравнением `location.hash === "#mini-app"`, а клиент Telegram дописывает к фрагменту свои параметры (`#mini-app?tgWebAppData=…`), поэтому заголовок авторизации не подставлялся и каждый запрос к `/api` получал 403. Разбор фрагмента приведён к правилу самого SDK Telegram; режим включается и после перезагрузки внутри WebView.
- Шлюз Mini App отдаёт страницу по адресу с `?project=<id>` (так выглядит адрес после выбора проекта); раньше перезагрузка WebView на нём получала 403 вместо страницы.
- Ответ 403 шлюза уходил с двумя противоречащими заголовками `Content-Length`; теперь длина ставится один раз.
- Диагностика Mini App различает «Telegram SDK не загрузился» и «Telegram не передал данные»; обёртка `fetch` больше не может уронить страницу исключением.
- Транспорт печатает локальный адрес Mini App при старте — по нему можно проверить шлюз, когда туннель недоступен.
- Для локальных проверок Bot API можно перенаправить на `http://127.0.0.1:<порт>` переменной `AIMASTER_TELEGRAM_API_ORIGIN`; любой другой адрес отклоняется, по умолчанию — прежний `https://api.telegram.org`.

Что проверено:

- Шлюз Mini App: битый тикет ассета с не-ASCII символами получает 403, а не обрыв соединения; при отклонённом теле запроса соединение закрывается, чтобы непрочитанные байты не стали «следующим запросом» на общем через туннель соединении. Переопределённый loopback-адрес Bot API не следует за редиректами: адрес с токеном не уйдёт на чужой хост. Найдено независимой проверкой кода перед выпуском.
- `python3 -m unittest discover -s skills/aimaster/scripts -p 'test_*.py'` — 79 тестов, OK (было 56: добавлены 9 E2E транспорта и 16 тестов Mini App, включая исполнение `mini-app.js` в `node`).
- `compileall`, `check_static_modules.mjs` (50 модулей), `git diff --check` — чисто.
- Локальный E2E транспорта живым процессом против mock Bot API на loopback: старт polling, callback `project:<id>` выбирает проект, четыре испорченных callback не останавливают опрос, следующие update обрабатываются, локальный шлюз Mini App после этого отвечает.
- Шлюз Mini App на живом сервере: валидный `initData` → 200 на `/api/projects`, `/api/session`, snapshot и `POST /api/actions`; отсутствующий, чужой, подделанный и протухший `initData` → 403 на всех `/api/*`.
- Экран Mini App в браузере с подменённым SDK: без SDK, с пустым `initData`, с невалидным `initData` (403), при обрыве сети — видимый экран ошибки с кнопкой «Повторить», не белая страница; с валидным `initData` и адресом в формате Telegram — рабочий дашборд.
- Дашборд с исправленным модулем открыт в браузере на синтетическом проекте: сценарий и раскадровка отрисованы, ошибок в консоли нет.

Что не проверено:

- Настоящий Telegram WebView и туннель `cloudflared` с реальным ботом — только ручная проверка владельца.
- Telegram Web (браузерная версия) открывает Mini App в iframe; дашборд отдаёт `X-Frame-Options: DENY`, так что там Mini App не откроется. Это политика безопасности всего дашборда, в этом выпуске не менялась.

# Выпуски AI Мастерской

Все опубликованные выпуски: https://github.com/alexfisenkov/aimaster/releases

## Как называем выпуски

- Первый выпуск за день: `2026.09.20`.
- Следующий за тот же день: `2026.09.20.1`, затем `2026.09.20.2`.
- Суффикс не нужен, если за день опубликован один выпуск.
- Используем дату в часовом поясе владельца проекта. Уже опубликованные
  названия не переносим на другой код и не переиспользуем.

## Что получает пользователь

Каждому выпуску соответствуют отметка в Git, страница выпуска и файлы VERSION
в корне репозитория и внутри навыка. Номер в обоих файлах одинаковый.
Официальные обновления приходят из этого репозитория; новые правила лицензии
нужно читать вместе с новым выпуском.

## Правило для владельца

Ветка main содержит публикуемую версию. Незавершённые изменения готовить
в отдельной ветке, а не предлагать пользователям как готовое обновление.
Перед выпуском обновить оба файла VERSION, сохранить изменения в Git,
создать новую отметку и опубликовать страницу выпуска для этого же коммита.
В описании отдельно указать, что изменилось и что действительно проверено.
Не заявлять успешные проверки, которые не выполнялись.

## 2026.09.21.3

- Для `per_scene` добавлен обязательный continuity choice перед каждой сценой после первой: previous accepted video, previous last frame или independent clip.
- При почти неизменной сцене агент рекомендует продолжение через scene-local `video_reference` с `usage=continue`, но сначала проверяет live schema модели.
- Предыдущее видео копируется в отдельный файл с новой ролью, оригинальный result не изменяется; rejected/hidden/retired/stale варианты не используются автоматически.
- В карточке следующей сцены появилась кнопка «Связать с предыдущей сценой» с точным project/scene/result контекстом.
- Выбор continuity теперь хранится в canonical scene state; runner блокирует генерацию каждой `per_scene`-сцены после первой, пока strategy и требуемый frame/video-reference не подтверждены read-back и не связаны с exact accepted result непосредственно предыдущей сцены.
- Тот же continuity guard применяется к payload-only `vary` и `regenerate`, поэтому старый результат не обходит обязательный выбор.
- Provider-native reference tags теперь проходят обязательную машинную проверку перед генерацией: карта содержит provider/route/model/revision/reference_id/asset_id, все inline-теги/mention chips должны точно присутствовать в финальном промпте, а structured inputs — иметь однозначные slots.
- Проверка ловит пропущенные и дублированные теги, оставшиеся canonical-теги, неподтверждённые rich mention chips и совпадения вроде `@img1` внутри `@img10`.
- Любой canonical `@IMG_NN`/`@VID_NN`/`@VOICE_NN`, которого нет в manifest как подтверждённого native token, блокирует запуск даже при пустом manifest.
- Для claimed jobs validator сравнивает manifest с точным frozen context из `claim`, включая полный набор canonical reference/asset IDs и revision; пропущенный текущий референс блокирует запуск.

## 2026.09.21.1

- Прикрепление готового image/video reference автоматически переводит существующий референс из `generate` в `upload`; активная позиция повторной генерации исчезает после read-back.

## 2026.09.21

- Выбор моделей строится по полному живому каталогу выбранного сервиса и требованиям конкретной задачи. Несовместимые модели исключаются с объяснением; доступны полезный shortlist и полный список совместимых вариантов.
- После каждой внешней генерации результат обязательно сохраняется локально, регистрируется в точной позиции Creator Studio и проверяется в дашборде до сообщения о завершении.
- Добавлен контроль завершения этапов: незакрытые результаты, варианты, QA, звук, сборка и следующий шаг больше не должны пропускаться молча.
- Превью изображений больше не обрезаются: сохраняются исходные пропорции, показываются размеры и соотношение сторон.
- По живому каталогу Magnific подтверждено, что Kling 2.5 нельзя предлагать для задачи с character/location references и 12 секундами; выбор должен производиться заново по текущей schema.

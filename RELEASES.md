# Выпуски AI Мастерской

Все опубликованные выпуски: https://github.com/alexfisenkov/aimaster/releases

## Как называем выпуски

- Первый выпуск за день: `2026.09.20`.
- Следующий за тот же день: `2026.09.20.1`, затем `2026.09.20.2`.
- Суффикс не нужен, если за день опубликован один выпуск.
- Используем дату в часовом поясе владельца проекта. Уже опубликованные
  названия не переносим на другой код и не переиспользуем.

## Что получает пользователь

Каждому выпуску соответствуют отметка в Git, страница выпуска и файлы VERSION
в корне репозитория и внутри навыка. Номер в обоих файлах одинаковый.
Официальные обновления приходят из этого репозитория; новые правила лицензии
нужно читать вместе с новым выпуском.

## Правило для владельца

Ветка main содержит публикуемую версию. Незавершённые изменения готовить
в отдельной ветке, а не предлагать пользователям как готовое обновление.
Перед выпуском обновить оба файла VERSION, сохранить изменения в Git,
создать новую отметку и опубликовать страницу выпуска для этого же коммита.
В описании отдельно указать, что изменилось и что действительно проверено.
Не заявлять успешные проверки, которые не выполнялись.

Минимальный набор проверок перед выпуском:

```bash
python3 -m unittest discover -s skills/aimaster/scripts -p 'test_*.py'
python3 -m compileall -q skills/aimaster
node --experimental-vm-modules --no-warnings skills/aimaster/scripts/check_static_modules.mjs
git diff --check
```

`node --check` для модулей дашборда не годится: файл, начинающийся с `import`,
он молча пропускает даже с синтаксической ошибкой. Поэтому модули
`studio/static` разбираются скриптом `check_static_modules.mjs` как настоящие
ES-модули.

## 2026.09.22.1

Что изменилось:

- Транспорт больше не останавливается от одной неудачной отправки. Раньше любая ошибка Bot API (обрыв сети, ответ 5xx, отклонённое сообщение) завершала процесс, а при перезапуске бот повторял ту же отправку и падал снова. Теперь сетевые сбои повторяются с нарастающей паузой, а сообщение, которое Telegram отверг (4xx), заменяется коротким уведомлением и не повторяется. В консоль печатается код и описание ошибки от Telegram (токен в текст не попадает).
- Bot API и проверка туннеля работают на Python без корневых сертификатов (установщик с python.org до запуска «Install Certificates.command»): клиент берёт сертификаты `certifi`, а без него — системные корни macOS. Проверка сертификатов не отключается.
- Проверка нового адреса туннеля больше не спрашивает его имя у системного DNS: соединение идёт на узел Cloudflare напрямую с именем туннеля в SNI. Ранний запрос имени оставлял в резолвере отрицательный ответ на полчаса, после чего адрес не открывался ни у транспорта, ни у Telegram на этом же компьютере.
- Надзор за туннелем ушёл в отдельный поток: пока идёт запуск и проверка, бот отвечает на команды. Раньше на время проверки (до минуты) бот молчал.
- Ответы, доставленные после перезапуска транспорта, снова несут кнопки навигации.

Что проверено:

- 144 теста, OK; `compileall`, `check_static_modules.mjs`, `git diff --check` — чисто.
- В настоящем Telegram владельца на этом выпуске: бот опубликовал новый адрес туннеля, имя разошлось по DNS (1.1.1.1, 8.8.8.8, системный резолвер), разделы «Сценарий» и «Промпты» отдали содержимое проекта, кнопка «Открыть AI Мастерскую» в сообщении открыла Mini App в Telegram Desktop с рабочим дашбордом проекта (шаг 4 из 6, результаты видео).

Что не проверено:

- Telegram на телефоне.

## 2026.09.22

Что изменилось:

- Разделы бота в Telegram — «Сценарий», «Промпты», «Результаты» — теперь показывают содержимое проекта, а не заглушку «Откройте AI Мастерскую для просмотра этого раздела». Сценарий: статус, текст, раскадровка по сценам. Промпты: референсы и промпты по кадрам (изображение и движение). Результаты: варианты по кадрам, что принято и что ждёт решения, звук, финальная сборка. Данные берутся из той же публичной проекции, что и у дашборда; приватные поля в чат не попадают. Длинные разделы уходят несколькими сообщениями (до трёх), кнопки — на последнем. Выбор проекта показывает краткую сводку. Фото-проекты без пустых видеоразделов.
- Временный туннель Cloudflare для Mini App запускается с пустым `--config`. Раньше `cloudflared` подхватывал пользовательский `~/.cloudflared/config.yml`, и если там уже настроен свой туннель с правилом «всё остальное → 404», запросы к временному адресу получали 404, а Mini App — пустой экран. Ваш конфиг при этом не читается и не меняется.
- За туннелем теперь следят: если `cloudflared` умер, транспорт перезапускает его с нарастающей паузой, публикует новый адрес в кнопку и меню бота, а пока адреса нет — убирает кнопку Mini App и сбрасывает меню, вместо того чтобы раздавать мёртвую ссылку. Туннель идёт по `--protocol http2`, его вывод читается постоянно (раньше заполненный буфер мог остановить процесс).
- Новый адрес проверяется до публикации, первая проверка — с задержкой, чтобы не закэшировать в локальном DNS отрицательный ответ. Если проверить с этого компьютера нельзя (имя ещё не разошлось; у Python нет корневых сертификатов), адрес публикуется с предупреждением в консоли, а не блокируется.
- Необязательно: постоянный публичный адрес Mini App через свой Cloudflare Tunnel — переменные `AIMASTER_MINI_APP_PUBLIC_URL` и `AIMASTER_MINI_APP_PORT`; тогда временный туннель не поднимается. Описано в `references/getting-started.md`.
- Клавиатура на многосоставном сообщении выбирается по индексу последнего куска, а не по совпадению текста.

Что проверено:

- `python3 -m unittest discover -s skills/aimaster/scripts -p 'test_*.py'` — 130 тестов, OK (было 79: +37 туннель, +24 разделы, обновлены транспорт и E2E). `compileall`, `check_static_modules.mjs`, `git diff --check` — чисто.
- В настоящем Telegram владельца до правки: кнопки «Сценарий» и «Промпты» отвечали одной и той же заглушкой; адрес Mini App в кнопках не резолвился; у работающего транспорта не было дочернего `cloudflared`.
- Живая проба туннеля на этой машине: с пользовательским `~/.cloudflared/config.yml` временный туннель регистрируется, но отдаёт 404 с обоих протоколов и с разных узлов Cloudflare; с пустым `--config` тот же туннель отдаёт 200 с первой попытки, запрос доходит до локального сервера.
- Разделы бота — на синтетических проектах (видео до сборки, фото, пустой, 40 сцен): три раздела дают разный текст с реальным содержимым, лимит 4096 на сообщение соблюдён, пути workspace в тексте не встречаются.

Что не проверено:

- Разделы и Mini App в настоящем Telegram после перезапуска транспорта на этом выпуске — проверяется вручную сразу после публикации.
- Реальная смерть `cloudflared` и перезапуск — только на подменённом процессе.
